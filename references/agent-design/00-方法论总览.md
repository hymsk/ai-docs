## 二、八条铁律（跨方向独立收敛，优先级最高）

1. **先澄清后生成是第一杠杆**：信息不足时分组提问、一次一题、HITL 中断确认；好的 Agent 不猜，而是升级求助（求助率健康区间 5–15%）。
2. **任务分解有效，堆 Agent 无效**：按领域结构切"专职子任务"（如需求=摘要→抽取→分类）；多角色流水线必须有评测数据支撑才引入（few-shot 单次调用击败过 8-Agent 流水线，两领域复现）。
3. **确定性打底 + LLM 增强**：AST/静态分析/RAG 提取事实，LLM 只负责把事实转译成人话；调用关系等结构必须确定性提取，不能指望模型自己看出来。
4. **强制溯源是反幻觉公共解**：每条关键论断附可验证出处（需求的 Trace-to-Source、代码的 file:line、架构的证据三级标签 fact/inference/open question）；无法证实的显式标注 `[待验证]` 或列 open questions 追问，禁止静默编造。
5. **生成只是开始**：第一天就设计增量更新——webhook/git diff 触发 > cron；内容哈希缓存省 60–90% token；更新以 diff/PR 形式交付，绝不静默覆盖。
6. **双受众文档**：人类稀缺注意力（渐进披露），Agent 稀缺 token（自包含页面、干净 Markdown、llms.txt/.md 直链）；机读文件做减法——泛化指令反而有害，只写模型推不出来的事实。
7. **人机协同是必要而非妥协**：AI 提案人类决策；自主度分档放权（建议→草稿→PR→全自动）；保护人写段落不被 Agent 触碰（对抗作者权流失）。
8. **评估驱动迭代**：三条硬指标——覆盖率（该写的写了吗）、真实性（引用的存在吗，Existence Ratio）、有用性（读者能用吗）。没有评测就没有架构决策权。

## 三、工程决策速查表

| 决策点 | 推荐 | 依据 |
| --- | --- | --- |
| 单 Agent vs 多 Agent | 默认单 Agent + 工具循环（ReAct 读码/检索）；仅在任务高度可并行且评测证明瓶颈后拆分 | Illusion of Agentic Complexity；IDRAAK 实验 |
| 知识注入 | RAG 为主力，微调仅补丁（风格对齐/私有化三条件才划算）；代码场景 Agentic 检索（grep/glob 自主探索）常优于向量 RAG | 混合检索贡献最大 MRR +24% |
| 框架 | 需要 HITL 中断/checkpoint/审计 → LangGraph 类显式状态图；框架差异远小于架构差异 | 需求生成长时序多人工点的特征 |
| 上下文管理 | 最小充分上下文：定义体+直接调用者+相关类型（几十~几百行）；超 ~100k token 质量反降；中间产物落盘为文件记忆而非对话历史 | WSCI 框架 |
| 成本控制 | Prompt 哈希缓存 + 模型分级路由（符号级摘要小模型、架构综合旗舰模型）+"该花的花"：低频高价值生成别用最便宜模型 | Litho 三层缓存 |
| 图表输出 | Mermaid（文本协议、可 diff、比 AI 绘图便宜 95%+），必须配渲染校验+自动修复闭环；中文文档警惕全角括号污染 | MermaidSeqBench |

## 四、交互设计必选项（MVP 就要有的六件事）

1. **意图预览**：动手前展示大纲/计划并获确认（尤其覆盖已有文档时）
2. **流式输出 + 阶段进度**：长文档必须流式；按"研究→大纲→章节→图表"展示进度
3. **证据引用可跳转**：悬停/点击论断跳源码行号——最强的可信度设计
4. **Diff 驱动更新**：一切修改走 diff/PR 审查视图
5. **操作审计 + 撤销**：时间线日志 + Undo，回退率目标 <5%
6. **置信度校准展示**：低质内容敢于示弱；注意 LLM 原始置信度需 Platt 校准后才可用于路由人工复核（ECE 可达 0.46）

完整模式库（含自主度旋钮、升级通道、可中断性 Addition/Revision/Retraction 三语义）见 [01-交互设计方向.md](01-交互设计方向.md) 第 4、13 章。

## 五、反模式红线清单

- ❌ 整仓/整规格塞 prompt → ✅ 抽取后精选最小充分上下文
- ❌ 一次性生成整篇巨著 → ✅ 大纲先行、分节并行、失败局部重试
- ❌ 无标签自信断言、静默编造 → ✅ 证据标签 + 待验证标注 + 追问机制
- ❌ 生成即不管 → ✅ webhook/delta/CI 门禁，否则等于制造新技术债
- ❌ 二进制绘图入库（draw.io/PNG）→ ✅ Diagram-as-code
- ❌ BLEU/ROUGE 当主要指标（与人类判断相关性弱）→ ✅ 存在率审计 + LLM-as-Judge + QA 式评测
- ❌ 黑盒长生成、无撤销、静默覆盖 → ✅ 流式 + 审计 + diff-first
- ❌ 把权限控制写进 AGENTS.md → ✅ 落在审批/沙箱/hooks 等真实控制面

## 六、落地路线模板（可直接套用）

```
Phase 1 MVP（1–2 周）
  单 Agent + 类型标准模板 Skill（SKILL.md + templates/）+ 结构化输出(JSON Schema 失败降温度重试)
  + 硬编码三条纪律：证据标签、模板符合性、不足则追问
Phase 2 规模化（2–6 周）
  分层/分节生成 + 缓存与 git diff 增量触发 + CI 自动开 PR
  + 确定性校验脚本（渲染/lint/必填节）+ LLM-as-Judge 评测基线
Phase 3 进阶（持续演进）
  变更影响分析精准重生成 + 双受众机读产物(llms.txt/AGENTS.md)
  + 新鲜度评分门禁(AST 锚点) + 人写段落保护协议 + 段落级反馈回流
```

各方向的详细阶段划分、量化指标口径与开源项目选型路径，见对应报告的"落地路线"章节。
